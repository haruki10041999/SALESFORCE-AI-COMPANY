# ADR-0001: 学習シグナルに対する報酬設計

日付: 2026-05-13

## ステータス

承認済み

## 背景

このランタイムは、テスト成功、デプロイ結果、PR readiness、トークンコスト、エラー復旧といった複数のシグナルから学習します。明示的な設計がない場合、システムは低コストだが低品質な出力へ収束するおそれがあります。

そのため、学習ループでは高コストな挙動を罰しつつ、コスト削減より品質改善を優先する必要があります。

## 決定

以下の形式の報酬モデルを採用します。

- reward = α·quality + β·success - γ·cost
- α は β と γ より大きくなければならない
- 品質を主軸に保つため、α は β + γ も上回らなければならない

実装詳細:

- [mcp/core/learning/reward-aggregator.ts](../../mcp/core/learning/reward-aggregator.ts) で共有の報酬重みを定義し、妥当性を検証する。
- [mcp/core/learning/replay-ab.ts](../../mcp/core/learning/replay-ab.ts) で、リプレイ変種のスコア計算前に報酬設計をアサートする。
- quality シグナルはフィードバックスコアとスコア調整値から導出する。
- success シグナルはツール実行成功率から導出する。
- cost シグナルはトークン使用量から導出し、スコアを減点する。

## 影響

ポジティブ:

- 低コスト・低品質な回答へ収束することを防げる。
- スコアリング意図が明示され、レビューしやすくなる。
- リプレイベース評価で一貫した適用ルールを持てる。

ネガティブ:

- ワークロード変化に応じて重み調整を定期的に見直す必要がある。
- 旧ランと比較した際にリプレイスコアが変動する可能性がある。
- 設計方針が明確な分、将来の変更時は本 ADR と対応するアサーションの更新が必要になる。
